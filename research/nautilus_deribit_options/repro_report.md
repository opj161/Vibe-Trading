## SOL skip decomposition (vs §82.3's "14 of 53" narrative)

21 of 53 SOL runs produced 0 legs for `opt_budget`: 7 are the `<2-dates`
run-level skip (53→46, per `TARGETS.md`), 14 are the option-entry-skip

## Platform limitation found (documented, not silently patched)

`BacktestVenueConfig`/`BacktestEngine.add_venue`'s `settlement_prices`
override does not wire into automatic option-expiry processing in
`nautilus_trader==2.0.0rc1` — see `postprocess.py`'s module docstring for
the full source-level finding (`crates/backtest/src/exchange.rs:636-645`
calls `matching_engine.process_instrument_expiration` directly, bypassing
`self.settlement_prices`, which is only consulted from
`process_instrument_close`, a different/manual code path). Worked around
in `postprocess.py` by using the leg planner's own precomputed
`intrinsic_per_unit` for expiry-leg settlement value instead of trusting
Nautilus's own strike-precision-rounded fallback fill price. Entry fills
and flip-exit fills are unaffected (both verified bit-exact against Vibe's
own price/quantity/fee formulas in Phase 3).

## Method note (Sharpe/MaxDD/duration-bucket reproduction)

Given the ≤$1.15-across-326-pairs bound above, the full daily-equity
Sharpe/MaxDD/duration-bucket table is reproduced by construction from
`leg_planner.py`'s own (Gate-2-exact) daily P&L series — recomputing an
independent Nautilus-side daily equity curve from 250 separate
single-run/single-track backtests would add engineering cost without
changing any conclusion, since the per-run totals that drive those metrics
are already shown to match to a bound 3-4 orders of magnitude below the
metrics' own sensitivity. Full artifacts: `derived/phase4_nautilus_vs_legplanner.csv`.

# Gate 6 — Mode B real-mark replay

**Scope reduction, documented (see `mode_b.py` module docstring for the
full reasoning)**: implemented as a real-mark re-pricing of Mode A's own
already-selected legs, not a full in-sim `subscribe_option_chain`/
`StrikeRange`/series-planner selection. Entry selection is unchanged from
Mode A because it is *already* print-gated (`selector.select_entry` only
ever returns an observed real trade) — the genuine realism gap the plan
targets is in *daily/exit marking* (Mode A prices every day after entry
from the BS-surface interpolation; Mode B re-prices those same days from
the nearest real observed `mark_price` print, falling back to a
coverage-skip when no print exists within a 5-day lookback). Building the
full `OptionChainSlice`-driven live-selection machinery is deferred (same
posture the plan itself takes toward Mode C/Tardis) — flagged as a Phase 8
follow-up if the live/paper bridge is ever built.

**Bug found and fixed during this phase**: `mode_b.py`'s first draft used
the tape's `mark_price` field directly as a USD value for both
underlyings. That is correct for SOL_USDC (linear, USD-native) but wrong
for BTC — the BTC tape's `mark_price`, like `price`, is BTC-denominated
and must be multiplied by that day's index price to reach USD (the same
§1.5 premium-convention asymmetry the whole project is built around).
Caught immediately by a ~20x-magnitude sanity failure on the BTC result
(H1 total collapsing to $124k from $1.5M, with the covered-shorts subset
showing a −2020% "improvement" — obviously wrong) before it was reported
as a finding. Fixed in `mode_b.py::realmark_leg` (`is_btc` param).

# Gate 7 — robustness grid

**Scope reduction, documented**: the plan's full grid is
budget{5} x DTE{3} x moneyness{3} x spread{3} x fallback{3} = 405 cells at
full Mode B / Nautilus-execution granularity — compute-prohibitive in this
session's time budget (each cell would cost ~2-4 minutes at Phase 6's

{14-30,20-40,30-60}, moneyness {5%,7.5%,10%}, spread multiplier {1x,2x,3x}),

proved Nautilus execution reproduces `leg_planner.py` exhaustively across
326 pairs to ≤$1.15, so a full-Nautilus 81-cell re-run would not change any
conclusion). BTC only (cross-asset generalization to SOL already
established in Phases 4-6). Fallback mode held fixed at "skip" (the only
implemented behavior — a run with no eligible option entry uses spot for
that run's H1 contribution, matching Vibe's own convention).

`leg_planner.plan_leg`/`plan_run_track` gained `dte_band`, `moneyness_band`,
`budget_frac` override params for this grid (defaults unchanged, verified
Gate 2 still reconciles exactly to floating-point noise after the change —
see `derived/` re-verification).

However, the *magnitude* of H1's edge is NOT flat — it ranges from

underlying notional, and shorter-dated options decay/reprice faster on the
whipsaw-cutting mechanism §82's own duration-bucket analysis already

discipline (CLAUDE.md, bar-boundary section): report the plateau, not the

itself reassuring (the originally-chosen parameters were not accidentally
picked at a fragile boundary).

## A.1 Bug fixed: native fee mode dropped the settlement fee on expiry legs

`postprocess.attribute_leg`'s `pnl_native` used the raw settlement value
for expiry legs, omitting the Vibe settlement fee that `pnl_parity`

## A.3 New diagnostic: what "held at Mode A" actually means for the
coverage-skipped Mode B runs

Because each leg's daily P&L telescopes, a leg's *total* is exactly
`exit_val − entry_cost − entry_fee` — intermediate marks never affect it.
Hence Mode B re-marking can only change **flip-exit** leg totals (via the
exit-day mark); **expiry-exit legs' totals are marking-independent and
already exact under any marking scheme**. Decomposing the
coverage-skipped short runs (`derived/phase6_uncovered_decomposition.txt`):

- BTC, 5 runs, +$449,704 held at Mode A = **+$600,200 expiry-exit
  (exact)** − $150,496 flip-exit (BS-approximated, all already-negative
  legs). Even a maximally adversarial re-marking of those flip legs
  (total premium loss) costs only ~$55k more — BTC's Mode-B H1 margin
  over spot (+$271k) is robust to *any* treatment of the uncovered legs.
- SOL, 3 runs, +$314,797 held at Mode A = **+$291,068 expiry-exit
  (exact)** + $23,730 net flip-exit (one +$69k winner, two small losers).
  SOL's Mode-B H1 margin over spot is +$74k, so an adversarial
  worst-case on the three uncovered flip legs (~−$177k swing) *could*
  flip SOL's Mode-B verdict — the realistic evidence points the other way
  (SOL's 17 covered runs re-marked *better* than BS by +$21.5k), but this
  is the honest fragility bound: **SOL's real-mark confirmation leans on
  expiry-settled legs (exact) plus a thin flip-leg margin.**
